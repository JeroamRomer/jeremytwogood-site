# Add-Video Skill — Design

**Date:** 2026-07-11
**Status:** Approved

## Goal

Adding a new video to jeremytwogood.com currently takes a full manual session:
watch the video, write copy, add two JSON entries, cut a hover loop, extract a
thumbnail, register the loop, run tests, commit. This design packages that into
a project-scoped skill (`.claude/skills/add-video/`) that drives the whole
pipeline as a **guided flow** — the agent does the work, but pauses at every
judgment point (copy, thumbnail, loop segment) for approval before writing.

## What is already automatic (skill must NOT duplicate)

- **Case-study page** — `src/pages/work/[id].astro` `getStaticPaths` generates a
  page for every `projects.json` entry that is not `coming_soon`/`comparison`.
- **Chatbot + MCP data** — `api/chat.ts` (via `chat-system.ts`) and the MCP
  tools both read `video-content.json`/`projects.json` at module load. One JSON
  edit feeds both; the live chatbot picks it up on the next Vercel deploy.
- **`agent-data.json`** — regenerated by `scripts/build-agent-data.js`, which
  runs as part of `npm run build` (locally and on every Vercel deploy).
- **Sitemap, VideoObject JSON-LD, breadcrumbs, OG tags** — all derived in
  `[id].astro` / `astro.config.mjs` from the data files.
- **Agent-discoverability artifacts** (spec `2026-07-11-agent-discoverability-design.md`,
  not yet built) — once shipped, generated `llms.txt` and enriched schema.org
  also flow from the same build step. No per-video action; the skill doc notes
  this so future readers don't think it's missing.

## Invocation

Conversational trigger only — no slash command. SKILL.md description matches
phrases like "add a new video", "publish this video to the site", "new case
study", "fill in the CAOT placeholder". Input is a YouTube or Vimeo URL plus
whatever metadata Jeremy volunteers; the skill asks for the rest.

Default scope is a **full case-study project**. The skill detects whether the
video fills an existing `coming_soon` placeholder (e.g. `caot-brand-film`) or
is a brand-new `projects.json` entry.

## Pipeline

Each step states what the agent does and where it pauses for approval.

### 1. Intake
Collect: URL, client, project name, type (e.g. "Advocacy Film · Documentary"),
disciplines, role array, year, `featured`, `span`. Check `projects.json` for a
matching `coming_soon` entry (fill it) vs. new entry (append). Derive the `id`
as kebab-case `<client-shortname>-<project-shortname>` matching existing
conventions.

**New-client check:** if the client is not in `profile.json`'s `clients` array,
ask whether to add it (feeds homepage clients section, chatbot, agent-data).

### 2. Watch
Run the `/watch` skill on the URL — transcript (captions or Whisper) + frames.
The downloaded video file in the watch working directory is **kept** and reused
for thumbnail and loop extraction (source = platform download; no local export
needed). Skip watch's step-5 cleanup until the pipeline finishes.

### 3. Draft copy — GATE
From watch output, draft the `video-content.json` entry:
`summary`, `mood`, `subjects`, `themes`, `transcript_excerpt`,
`agent_description` (see the `ttms-chef-nuit` entry for the house style —
agent_description ends with runtime and series context; summary is one dense
paragraph). Show the full draft; take edits; loop until approved.

### 4. Thumbnail — GATE
Present options side by side:
- The platform's hosted still (YouTube `img.youtube.com/vi/<id>/maxresdefault.jpg`,
  Vimeo via oEmbed `thumbnail_url`) — zero-cost, used by 2 of 8 current projects.
- 3–4 candidate frames extracted from the downloaded video by
  `scripts/extract-frames.sh` (spread across the runtime, biased toward
  high-detail frames).

Jeremy picks one. If a local frame: export at source resolution to
`public/assets/<short-name>-thumb.png` (short-name convention, like loops:
`talkto-thumb`, not `ttms-chef-nuit-thumb`), then **compress with `sharp`**
(`scripts/compress-thumb.mjs`, target ≤ 300 KB, max width 1600px, jpg or png
per content). Hosted URL: just record it in `projects.json`.

### 5. Hover loop — GATE
`scripts/make-loop.sh` proposes a ~4 s high-motion segment (ffmpeg scene-change
scoring), cuts a preview MP4, shows it (open in Preview/QuickTime or dev
server). Jeremy approves or supplies a different timestamp; re-cut until happy.
Final encode matches existing loops exactly:
- 960×540, 24 fps, muted, ~4 s
- `<name>-loop.mp4` (h264, ~450 kbps, faststart) + `<name>-loop.webm` (vp9)
- target ≤ 300 KB each, written to `public/assets/`

### 6. Write data
- `projects.json` — fill or append the entry (schema per existing entries:
  `id, name, client, type, disciplines, year, role[], youtube_id+youtube_url
  (or vimeo_id+vimeo_url), thumbnail, featured, span` — unused fields omitted;
  legacy `link` field is dead).
- `video-content.json` — add the approved entry under the project `id`.
- `src/components/Projects.astro` — add `'<id>': '<name>-loop'` to the
  `previews` map.

### 7. Optional reel clip
Ask: "add this to the showreel index too?" If yes, append a clip object to
`reel-index.json` (name, description, client, role, timestamps, video_url).

### 8. Verify
- `npm run build` (regenerates `agent-data.json`; will also regenerate
  discoverability artifacts once that project ships)
- `npm test` and `npm run test:api`
- Start the dev server (`.claude/launch.json`), then check in the browser:
  homepage card renders + hover loop plays, case-study page `/work/<id>`
  renders copy/meta/player, project count reads correctly.

### 9. Commit — GATE
Show a diff summary. Commit only on approval. Push is a separate explicit ask
(push = deploy, since Vercel auto-deploys `main`).

### 10. Post-deploy live check (optional, after Jeremy pushes)
- `curl -sf https://www.jeremytwogood.com/work/<id>` returns 200 and contains
  the project name.
- Ask the live chatbot (`POST /api/chat`) one question about the new video and
  confirm a grounded answer — proves the deployed system prompt picked up the
  new data.

## Companion code change (one-time, shipped with the skill)

`Projects.astro` line 24 hardcodes `08 Projects · 2016—2026`. Derive it
instead: count from `projects.length`, year range from min/max `year` fields
(zero-padded count, em-dash range). Removes a stale-string trap from the
pipeline permanently — the skill then needs no step for it. Covered by a smoke
test asserting the rendered count matches `projects.json`.

## Deliverables

```
.claude/skills/add-video/
  SKILL.md                    # the guided pipeline (this design, operationalized)
  scripts/
    extract-frames.sh         # candidate thumbnail stills from a video file
    make-loop.sh              # scene-pick + cut + dual encode (mp4/webm)
    compress-thumb.mjs        # sharp compression to ≤300 KB
src/components/Projects.astro # derived count string (companion change)
tests/smoke.test.js           # + derived-count assertion
```

Scripts are deterministic and idempotent — encode settings live in the scripts,
not in prose, so every future loop matches the existing six.

## Error handling

- `/watch` download fails (login/region-locked) → report plainly, offer local
  file path as fallback source for frames/loop; copy can proceed from a
  Jeremy-provided description if transcript is unavailable.
- No ffmpeg/sharp → point at `brew install ffmpeg` / `npm i` (sharp is already
  in package.json).
- Tests fail at step 8 → stop, show output, fix before commit gate.
- Vimeo oEmbed thumbnail 404s → fall back to extracted frames only.

## Out of scope

- Reel video replacement / reel-index rebuild (placeholder redesign is its own
  project).
- resume.json updates (not per-video).
- Social announcements, YouTube upload/metadata (site-side only).
- Automating the push/deploy itself.
